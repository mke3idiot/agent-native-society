# 作者原則 / Author principles v1.0.0

**状態:** 2026-09-04に追加した作者コンテキスト。原典の意味を変更しない運用原則である。

## 中心命題

技術は目的ではない。人間の不自由、維持コスト、手作業、将来の負債を減らし、人間が目的を伝えればシステムが動ける状態をつくるための手段である。

AIは単なる画面上の機能ではなく、今後は、正当な委任と責任のもとでサービスを利用・実行する主体になる。この前提から、Agent Native Societyを社会の目標、AI Optimization / AI最適化を移行方法論、Agent Readyを安全に使えるサービスの状態、MCP / API / A2A / UCP等を技術手段として位置づける。

## 設計原則

- 構造的に古い仕組みを「今変えると大変」という理由だけで温存しない。
- 流行やベータ版を追うこと自体は目的にしない。一方、構造的に優れた移行には「今より早い日」はない。
- AIに人間の画面操作を模倣させるより、AIが直接・安全にシステムを利用できる構造を選好する。
- 特定のAI、モデル、ベンダー、またはプロトコルへ思想を従属させない。
- 目的、思想、仕様、実装を混同しない。ただし相互の追跡可能性を保ち、すべてをリポジトリのSSOTへ残す。
- 増える手間には、それに見合う明確な成果が必要である。成果を増やさない手間は負債である。
- 便利さの一時点最適より、将来の変更容易性、交換可能性、構造の単純さを重視する。
- 小さな便利ツールへ早期に収束せず、人とシステムの関係や社会構造の変化まで射程に入れる。
- 抽象論で終わらせず、実装・運用・事業化ができる形に落とす。
- 既存の正しさへの同調より、目的に対する構造的な正しさを優先する。

## 思想の扱い

思想は固定物ではない。変更時には過去を消さず、何が変わり、なぜ変わったかを新しい記録として残す。先行性を根拠なく主張せず、重複・影響・反証はprior artと研究記録に明示する。
