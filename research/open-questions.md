# Open questions v1.0.0

## Verified framing

The foundational documents identify delegation, identity, semantics, commitment, safety, observability, recourse, and interoperability as requirements for Agent Ready services. This list is an agenda derived from those documents; it is not evidence that solutions exist.

## Priority questions

1. What is the smallest portable delegation object that captures purpose, scope, limits, approval requirements, expiry, revocation, and evidence without over-centralizing identity?
2. How should a capability contract express material side effects, commitment states, reversibility, price/terms freshness, and recourse in a machine-verifiable way?
3. Which Agent Ready maturity levels are useful to providers and principals without becoming misleading certification theater?
4. What policy architecture can resist prompt injection and confused-deputy failures when an agent processes untrusted provider content?
5. Who pays for Agent Ready migration, and what measurable benefit accrues to providers, users, and intermediaries at each risk tier?
6. How can evidence be sufficient for audit and dispute while minimizing personal-data retention?
7. Which initial vertical has a bounded enough commitment surface to validate the architecture, but a meaningful enough business pain to avoid toy-demo status?
8. How do consumer protection, sector regulation, agency law, payments, and cross-border rules change the feasible operating model?

## Hypotheses to test

- A provider-facing Agent Ready assessment plus a policy/evidence gateway may create more durable value than another general-purpose agent runtime.
- Commitment-aware capability contracts will reduce harmful ambiguity more than generic tool schemas alone.
- A narrow, reversible transaction flow is sufficient to demonstrate the distinction between agent capability and agent authority.

These are hypotheses, not product claims.
