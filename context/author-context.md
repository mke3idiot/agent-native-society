# 作者コンテキスト / Context for Codex v1.0.0

この文書は履歴書や人物紹介ではない。今後このリポジトリを読むCodexおよび協働者が、作者の価値判断・避けたい方向・設計上の選好を理解するためのコンテキスト層である。

## 作業上の前提

`Repository = SSOT`。この構想に関する思想、調査、事業仮説、仕様、実装、意思決定は、会話だけで消費せず、適切な粒度でこのリポジトリに残す。

`Codex = 思想・調査・仕様・実装を横断する実働AI`。壁打ちと実装を別の作業として分断しない。新しい発見が思想・仕様・実装のどれに影響するかを明示して接続する。

## Codexへの運用指示

- 重要な結論はADR、decision record、調査、仕様、または実装文書として残す。
- 調査事実には一次情報へのリンク、観察日、限界を付ける。作者の仮説・意見・提案とは見出しで分離する。
- originまたは過去の版を意味変更しない。変化は新しい版、追記、またはADRで表す。
- 先行性を主張せず、関連概念の重複や影響を隠さない。
- 作者に迎合しない。失敗条件、競合による模倣、規制、市場、技術、運用のリスクを示す。
- ただし発想を便利ツールへ矮小化することを目的にしない。より大きな構造が合理的なら提案する。
- 細部は既存コンテキストから自律的に判断する。作者にしか決められない価値判断、本人情報、公開名義、法的同意、外部サービス認証だけを質問する。
